Nebula DBA / Feature plan / 3 November 2026

Compressed backups. Fewer prerequisites.

Add an accessible compression switch to the existing backup form and ship Microsoft's standalone SQLCMD client inside the Windows app.

Backup behavior

  • Detect SQL Server backup-compression support from its engine edition and edition name. Enterprise, Standard, Developer and Evaluation are supported; Web, Express and unknown editions are not.
  • Show “Compress backup” only for eligible online databases other than tempdb. Default it to on when selecting a database; allow switching it off before backup.
  • Validate the boolean option in the trusted backend, recheck database capability, and explicitly request COMPRESSION or NO_COMPRESSION while preserving copy-only backups and checksum verification.

Installation

  • Bundle pinned Microsoft Go SQLCMD 1.10.0 with a SHA-256-verified download, its license and upstream third-party notices. Exclude its debug executable.
  • Use the bundled executable by absolute path, without relying on an external SQLCMD or ODBC installation.
  • Remove the Chocolatey sqlserver-cmdlineutils dependency, which introduces ODBC and Visual C++ redistributable dependencies. SQL Server itself remains user-managed.

Validation and delivery

  1. Test edition detection, option validation, explicit opt-out, and rejection on unsupported editions.
  2. Use uniquely named disposable databases for real compressed/uncompressed backups, verification, restores and post-restoration scripts. Do not modify existing user databases.
  3. Exercise the switch, IPC and operation lock in Electron, and inspect both existing themes.
  4. Build version 0.2.0-beta.1, validate the packaged client and executable names, commit and push, then publish a GitHub prerelease with a versioned EXE and checksum for user testing.
