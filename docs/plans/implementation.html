NEBULA / LOCAL DATABASE OPERATIONS

Backup & restore, close to home.

A Windows Electron application for administering the local SQL Server with a searchable database sidebar and a focused backup and restore workspace.

01 · Desktop foundation

React, TypeScript, Tailwind and Lucide in a sandboxed Electron renderer. A narrow preload bridge delegates SQLCMD and filesystem operations to the main process. No cloud backend or separate application sign-in: SQL Server uses the current Windows identity.

02 · Connection & discovery

Visual direction follows the supplied Nebula brand guide, edition 1.1: Segoe UI, deep teal surfaces, cyan selection and focus, orange primary actions, and complete Light, Dark and System modes with a saved preference.

Attempt localhost on launch; discover local named instances as fallbacks. Allow choosing a local instance and reconnecting. Surface connection failures with actionable messages and never show fabricated databases.

03 · Backups

Choose and persist a backup root using the native folder picker. Create a database-named subdirectory, then a unique timestamped .bak file. Full copy-only backups use checksums and verification. Display local backup files with size and date.

04 · Restore

Select a local .bak file, verify it, and restore to the selected user database. Require an explicit overwrite confirmation naming the target database. Disconnect active sessions only after confirmation, and recover multi-user mode on failure where possible. Exclude system databases from destructive restore operations.

05 · Verification & delivery

Run type checks, lint, automated safety tests, and a production build. Exercise SQL discovery against the installed instance. Validate backup/restore using an isolated disposable test database if feasible. Package a Windows executable and document setup and limitations.

SQL Server's service account must be able to read and write the chosen backup directory. The application will explain permission errors without modifying system ACLs automatically.

Questions

No blocking questions. Initial scope is local Windows authentication and full database backups/restores. SQL logins, scheduling, point-in-time recovery and restoring under a new name can be added later.
